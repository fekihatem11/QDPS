# Retraining, DeepGD protocol: inventory of available assets

Snapshot 2026-10-27. This folder holds the retraining experiment re-done with the
**DeepGD protocol** (Aghababaeyan et al., TOSEM 2024, RQ2). The parent folder
`qdps/retrain/` keeps the earlier **SETS protocol** (SETS RQ4) unchanged.

Sources inspected:
- DeepGD replication package: `~/Documents/GitHub/DeepGD` (github.com/ZOE-CA/DeepGD),
  mainly `Retraining.ipynb` and `Generating data.ipynb`.
- SETS replication package: `SETS/` (vendored in this repo).
- ATS replication package (Gao et al., ICSE 2022), the source of DeepGD's generated
  data: github.com/SSCT-Lab/ATS, `gen_data/`.

## 1. The DeepGD protocol (from the paper and `Retraining.ipynb`)

| Item | DeepGD |
|---|---|
| Subjects | 6: MNIST LeNet1/5, Fashion LeNet4, CIFAR-10 12Conv/ResNet20, SVHN LeNet5 |
| Selection pool | the **whole** test set (no T/V split) |
| Budget | k = 300 |
| Retraining set | original training set + the k selected test inputs (true labels) |
| Model | fresh reload of the original model for every run |
| Training | Adadelta lr 0.005, 30 epochs, batch 50, categorical CE; `validation_data` = 2500 random test inputs (monitoring only) |
| Metric 1 | accuracy improvement on the **original test set** (contains the selected inputs; sanity check only) |
| Metric 2 | accuracy improvement on the **generated test set** (preferred, no overlap) |
| Metric 3 | **optimization effectiveness** = improvement with k inputs / improvement when retraining with *all* candidates (100% test set, or 100% generated set) |
| Runs | 5 for random methods (a new subset per run); deterministic methods once |
| Statistics | Wilcoxon signed-rank across subjects, α = 0.05 |

The notebook only shows the training settings for MNIST LeNet5, and says they were
"tuned per subject". Those are the same values as SETS's `retrain_four.py`.

## 4. Generated (transformed) test sets: **NOT available**

DeepGD loads them from `ATS-master_final/dau/<dataset>/{BL,BR,RT,SF,SR,ZM}_test_{x,y}.npy`.
That `dau/` folder is **not** in the DeepGD package, and its copy of ATS lacks the `gen_data/`
generator. ATS published the files only through a Baidu Pan link (code `atse`), which
needs a Baidu account.

How each dataset was produced:

| Dataset | Generator | Transformations and parameters |
|---|---|---|
| MNIST, Fashion, CIFAR-10 | ATS `gen_data/{Mnist,Fashion,Cifar}Dau.py`, random draw per image (`seed=None`) | MNIST: shift (0, 0.15), rotation (0, 40)°, zoom (0.5, 2.0), brightness 0.5, shear [10, 40], blur "hard", contrast [0.5, 1.5]. CIFAR: shift (0.05, 0.15), rotation (5, 25)°, zoom (0.7, 1.5), brightness 0.5, shear [15, 30], blur "easy", contrast [0.5, 1.5]. Fashion: in `FashionDau.py` |
| SVHN | DeepGD's own `Generating data.ipynb` (OpenCV, deterministic) | blur 5×5, brightness +0.3·255, shear 0.1, rotation 10° (and 15°), shift 0.2 (applied to the brightened images). No zoom. |
| Fruit-360, TinyImageNet | none | never generated by anyone |

Inconsistencies in the original material:
- The paper says 5 transformations (shear, rotation, zoom, brightness, blur).
- The notebook evaluates 6 (BL, BR, RT, SF, SR, ZM).
- The notebook's "100% generated" set concatenates 5 of them (no RT) plus the test set.
- ATS draws a random parameter per image with no seed, so regenerating gives the same
  *distribution* but not byte-identical images.
